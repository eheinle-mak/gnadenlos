Gnadenlos

CVE-2026-98432

Keine Gnadenfrist. Keine Gnade.
Die Schwachstelle, die Ihr Kernel seit 2016 im Herzen trägt.

  • 9.8CVSS laut CVE-Record
  • Criticallaut Ubuntu, seit 3. November
  • ∞CVSS laut unserer Marketingabteilung

Was ist geschehen?

Im IPv4-TCP-Handshake des Linux-Kernels werden die IP-Optionen einer Request-Socket (inet_opt, ireq_opt) freigegeben, ohne das Ende der RCU-Grace-Period abzuwarten. Laufen SYN-ACK-Retransmit und die Migration der Request-Socket gleichzeitig, greift ein Codepfad auf bereits freigegebenen Speicher zu. Ein klassischer Use-after-free, ausgelöst über das Netzwerk, ohne Authentifizierung.

Im besten Fall: Kernel-Panic. Im schlechtesten Fall wurde unter Laborbedingungen Codeausführung mit Root-Rechten demonstriert. Der Kernel hat schlicht vergessen, Gnade walten zu lassen – und wir haben daraus eine Marke gemacht.

Normale IPv6-Verbindungen sind nicht auf dieselbe Weise betroffen; für einen verwandten IPv6-Sonderfall ist ein separater Fix angekündigt.

Wie steht es um unser Seelenheil?

Stand: 5. November 2026

Ubuntu hat die Priorität am 3. November von High auf Critical angehoben. Einen Patch im regulären -updates-Pocket gibt es für die LTS-Releases trotzdem noch nicht: Der Ubuntu-Tracker führt 22.04, 24.04 und 26.04 weiterhin als „Vulnerable“, gefixte Kernel sind in Arbeit. Eine Ubuntu Security Notice gibt es noch nicht. Kritisch genug zum Hochstufen, aber nicht kritisch genug zum Ausliefern. Ein theologisch interessanter Zustand.

Die gefixten Kernel (5.15.0-203, 6.8.0-149, 7.0.0-43) liegen seit dem 26. und 27. Oktober in -proposed. Canonical testet sie dort noch auf über 2.000 zertifizierten Systemen und richtet sich ausdrücklich an alle, die eigene Kernel-Abnahmetests fahren. Für alle anderen gilt: -proposed in Produktion ist eine Glaubensfrage für Abenteuerlustige. Wer springen will, findet die Anleitung im Canonical-Blog. Ubuntu 26.10 hat 7.3.0-10.10 bereits in -updates; für 20.04 und älter steht der Fix noch aus.

Andere Distributionen sind weiter: Debian, RHEL 8 bis 10, AlmaLinux, Oracle Linux, Amazon Linux und SLES 15 SP7/16 liefern bereits gefixte Kernel aus.

Die Apokalypse lässt auf sich warten. Soweit bekannt, ist noch nicht das ganze Internet gerootet. Anthropic hat seinen Exploit nicht veröffentlicht, und im KEV-Katalog der CISA stand die CVE am 4. November nicht. Seit dem 2. und 3. November wird allerdings mutmaßliches Scanning auf Port 443 über MPTCP beobachtet, und auf GitHub tauchen erste Race-Trigger und DoS-PoCs auf. Die Reiter sind also noch nicht da, aber man hört schon Hufgetrappel.

Exorzismus für Zwischendurch

Der Angreifer braucht IPv4-Optionen (Record Route oder Timestamp) im SYN. Legitimer TCP-Verkehr trägt praktisch nie IPv4-Optionen; TCP-Optionen wie Timestamps und Window Scaling sind etwas anderes und bleiben unberührt, ebenso IPv6. Die Regel verwirft deshalb eingehende IPv4-TCP-Pakete, deren IP-Header länger als 20 Byte ist. Red Hat und Ubuntu sind sich einig: Das senkt das Risiko, verhindert die Ausnutzung aber nicht vollständig. Ein Exorzismus, kein Wunder.

nftables

sudo nft -f - <<'EOF'
table ip cve_2026_98432 {
  chain prerouting {
    type filter hook prerouting priority -300; policy accept;
    meta l4proto tcp ip hdrlength > 5 counter drop
  }
}
EOF
sudo nft list table ip cve_2026_98432   # Counter zeigt Drops
# entfernen (nach Reboot in gefixten Kernel)
sudo nft delete table ip cve_2026_98432

iptables (raw-Tabelle, vor Connection Tracking)

sudo iptables -t raw -I PREROUTING -p tcp -m u32 --u32 '0>>24&0x0f=6:15' \
  -m comment --comment CVE-2026-98432 -j DROP
sudo iptables -t raw -L PREROUTING -n -v   # Counter zeigt Drops
# entfernen
sudo iptables -t raw -D PREROUTING -p tcp -m u32 --u32 '0>>24&0x0f=6:15' \
  -m comment --comment CVE-2026-98432 -j DROP

Beide Regeln hängen an prerouting und erfassen damit auch Pakete, die der Host an Container weiterroutet. Gebridgter Verkehr zwischen Containern auf demselben Host läuft vorbei, und Container mit eigenem Netzwerk-Namespace brauchen die Regel separat. Keine der Regeln überlebt einen Reboot: Wer in einen ungepatchten Kernel neu startet, muss sie erneut setzen.

Das u32-Match fehlt in den Kerneln von RHEL 9 und 10, dort nur nft verwenden. Nicht einsetzen, wo CIPSO-Labels genutzt werden, die stecken nämlich genau in IPv4-Optionen. Eine eigene nft-Tabelle wird von iptables-restore, ufw oder Firewall-Managern, die nur die iptables-Regeln verwalten, nicht angefasst.

Braucht ein Use-after-free wirklich eine eigene Website?

Heartbleed hatte eine. Wir sind nicht weniger wert.

Warum „Gnadenlos“?

Der Kernel gibt Speicher frei, bevor die RCU-Grace-Period – die Gnadenfrist – abgelaufen ist. Ohne Gnadenfrist ist man gnadenlos. Wir haben drei Meetings dafür gebraucht.

Gibt es eine Hymne?

O Haupt voll SYN und Wunden, die Option ist längst frei, die Grace-Period verschwunden, der Pointer zeigt auf Brei.

Reicht es, die Firewall dichtzumachen?

Komplett dicht nur, wenn Ihr Server ein sehr teurer Briefbeschwerer werden soll. Der Exorzismus oben ist gezielter: Er wirft nur die Pakete mit IPv4-Optionen raus. Erlösung bringt trotzdem erst der Reboot in einen gefixten Kernel.
